THE IDEA

A repair loop you can trust.

Rebuildable treats “it should work” as a hypothesis. The repository is checked in layers, failures are named, and each fix earns its way into the next run.

A broken repository is not a blank page. It is a map of near-misses waiting to be made explicit.

01

Start with the smallest signal.

Read the tree, manifests, and actual error before reaching for a broad rewrite.

02

Make progress measurable.

Every run reports the same eight checks, so improvement is visible instead of anecdotal.

03

Leave a useful trail.

Repairs should be understandable to the next person—and easy to verify from a clean checkout.

THE REPAIR CONTRACT

Eight checks.
One honest score.

The checks cover the signals that make a small repository safer to rebuild. A pass is evidence, not optimism.

01 / 08

Git history

Require a Git repository with at least one commit so the clean-machine input is reproducible.

evidence HEAD commit
02 / 08

Dependency lock

Find a supported lockfile, or a requirements.txt whose every dependency is pinned with ==.

evidence lockfile
03 / 08

Runtime pin

Confirm that Node or Python has an explicit version in a version file, engines, or pyproject.

evidence runtime declaration
04 / 08

Docker build

Require a Dockerfile with FROM, a lockfile install, and CMD or ENTRYPOINT.

evidence build + run contract
05 / 08

Test command

Find a package.json test script, pytest configuration, or Makefile test target.

evidence repeatable test
06 / 08

README steps

Check that README headings describe Setup, Run, and Test steps for the next operator.

evidence Setup / Run / Test
07 / 08

Settings and secrets

Require .env.example and scan source, config, and docs for common hardcoded secret patterns.

evidence redacted settings
08 / 08

Relative paths

Reject author-machine paths such as home directories and Windows user folders in project files.

evidence portable paths

THE LOOP

Evidence → repair → proof.

Repeatable work is calm work. Keep the feedback tight, keep the change small, and let the next run tell you what moved.

01 / SCAN

See the failure clearly.

Inventory the workspace and run the checks without hiding the first useful error.

→
02 / FIX

Repair the smallest cause.

Restore missing structure, commands, or contracts in a way a human can review.

→
03 / VERIFY

Earn the next green.

Run the same eight checks again and keep the evidence that moved the score forward.
